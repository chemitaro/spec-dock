なぜ修正するのか

Before S04 exact-file runtime context

  • 通常 authoring のたびに scoped-context --discussion-file を使う。
  • 1 run で 1 file の write root を生成するため、複数 scope の draft 作成が重い。
  • 静的 adapter だけを見ると read-only fallback に近く、role classification が分かりにくい。
  • file-based context persistence を重視する方針に対して、実行前準備の概念が多い。

After S05 static all discussions write

  • 2 role には静的に all scope-local discussions/ write capability を付与する。
  • run ごとの agent setting rewrite や exact-file context generation を標準経路にしない。
  • canonical docs は main orchestrator の single-writer authority として残す。
  • post-run diff guard と reviewer gate で採用資格を閉じる。

目標モデル

設計の芯: sub-agent の知見は会話 context ではなくファイルへ残す。ただし canonical docs への最終統合責任は main orchestrator が持つ。
