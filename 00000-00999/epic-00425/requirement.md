# epic-00425 Build Html Spec Dashboard And Cue Documents — 要件定義

詳細: [Requirement Guide](../../../docs/authoring/requirement.md)

表示名：仕様を HTML のダッシュボードで見渡し、仕様の文書を CUE で書く

> この文書は、2026-10-25 に利用者から聞いた構想の下書きである。要件の議論は、epic-00424 を終えた後に行う。それまでは、ここに書いたことを決定として扱わない。

## 目的

SpecDock で管理する仕様を、1か所の正本から、人が全体を見渡せる HTML のダッシュボードで示す。仕様の文書は、エージェントが確かめるための CUE で書き、人には分かりやすい HTML で見せる。

利用者の言葉では、これまでのプログラミングは「点」だった。SpecDock で「面」にし、さらに時間の軸を加えた立体的な管理ができるようにする。

## 背景

### 親の Initiative と、前の Epic との関係

- epic-00424 で、仕様の内容の正本は `spec-dock/canonical`（各PCのカタログ）に、構造の正本は GitHub Issue に、それぞれ1か所になる。この Epic は、その1か所の正本を読んで表示する。
- epic-00424 は、GitHub の構造を一括で取得し、PCのユーザーごとに1つのファイル（構造のスナップショット）として持つ仕組みを作る。この Epic のダッシュボードは、そのファイルを読み、操作のたびに GitHub に問い合わせない（GitHub の負荷と待ち時間を抑えるため。利用者の要望）。
- epic-00424 では、つなぎとして、今までと同じ Markdown と PlantUML のダッシュボード（`spec-dock/dashboard.md` など）を、定期の同期が作り直す。この Epic の HTML のダッシュボードは、それを置き換える。

### 利用者の構想（2026-10-25）

ダッシュボード：

- HTML で作る、レスポンシブで使いやすいウェブの画面にする。
- Initiative、Epic、Issue の縦の階層（親子）と、作業の順番の依存（blocked by）を、図で示す。
- 状態を色で示す。実装中のもの、まだ始めていないもの、止められているもの（依存が終わっていない）、終わったもの。
- 終わったものを隠す表示と、終わったものを含めてすべてを示す表示を切り替えられる。
- 1つの Epic や Issue を選ぶと、詳しい画面を開ける。詳しい画面には、次を示す。
  - GitHub の日本語の題名。
  - 依存しているもの、依存されているもの。
  - 配下に含むもの。
  - その Scope の中での、実行の順番の依存。
  - その Scope の要件、設計、計画の内容。

仕様の文書：

- 今の Markdown の要件定義書、設計書、計画書を、CUE で書く形に移す。CUE の文書は、人が読むことを前提にせず、エージェントが確かめるためのものとして作り込む。
- 人には、CUE から作った分かりやすい HTML の資料で見せる。
- ダッシュボードは、1か所の正本から、今の要件、設計、計画をその場で描き、一部を画面に組み込んだり、人向けのページを開いたりできる。
