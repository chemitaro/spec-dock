# epic-00425 Build Html Spec Dashboard And Cue Documents — 要件定義

詳細: [Requirement Guide](../../../docs/authoring/requirement.md)

表示名：仕様の文書を CUE で書き、人には HTML で見せる

> この文書は、2026-10-25 に利用者から聞いた構想の下書きである。要件の議論は、epic-00424 を終えた後に行う。それまでは、ここに書いたことを決定として扱わない。
>
> 2026-10-25 に、HTML のダッシュボードを、この Epic から epic-00427（#427「Build Html Spec Dashboard」）に分けた。この Epic は、仕様の文書を CUE と HTML に移すことだけを扱う。GitHub の題名は作成時のまま（ダッシュボードを含む）である。

## 目的

SpecDock で管理する仕様の文書（要件定義書、設計書、計画書など）を、エージェントが確かめるための CUE で書き、人には分かりやすい HTML で見せる。

利用者の言葉では、これまでのプログラミングは「点」だった。SpecDock で「面」にし、さらに時間の軸を加えた立体的な管理ができるようにする。この Epic は、その「面」を作る文書の側を受け持つ。

## 背景

### 親の Initiative と、ほかの Epic との関係

- epic-00424 で、仕様の内容の正本は `spec-dock/canonical`（各PCのカタログ）に、構造の正本は GitHub Issue に、それぞれ1か所になる。この Epic の文書は、そのカタログに置く。
- epic-00427 の HTML のダッシュボードは、この Epic が CUE から描いた HTML を、詳しい画面に組み込み、人向けの説明の HTML へのリンクを示す（epic-00427 の段階2）。ダッシュボードの構造の画面（段階1）は、この Epic の前に出す。

### 利用者の構想（2026-10-25）

- 今の Markdown の要件定義書、設計書、計画書を、CUE で書く形に移す。CUE の文書は、人が読むことを前提にせず、エージェントが確かめるためのものとして作り込む。
- 人には、CUE から作った分かりやすい HTML の資料で見せる。
- 1か所の正本から、今の要件、設計、計画をその場で描き、ダッシュボードの画面に組み込んだり、人向けのページを開いたりできる。

### epic-00427 からの依頼（2026-10-26）

- 人向けの説明の HTML の置き場と見分け方を決める。ダッシュボードがリンクを示すためである。
- CUE から HTML を描く部品を、ダッシュボードのサーバーから、その場で呼べるようにする（epic-00427 の R-E9）。
