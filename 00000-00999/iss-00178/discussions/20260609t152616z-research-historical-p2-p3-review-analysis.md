## 結論

過去の実例を広く見ると、Codex Review の P2 は「軽微な好み」よりも、実際の欠陥、回帰、復旧不能、誤判定、外部副作用、テスト実行不能を指摘しているケースが多い。したがって `P2 だから原則無視` は危険である。

ただし、`P2 をすべて current PR で直す` も過剰である。docs / diagnostics / test coverage / operator clarity のような finding は、低コストなら直し、大きくなる場合は follow-up に切るのが妥当である。

実務上は、P2/P3 に `risk class` と `disposition` を必ず付け、`must_fix` が残っている場合は blocked、non-blocking finding が分類済みなら `merge-prepared` として人間判断に渡す運用が最も安定する。
