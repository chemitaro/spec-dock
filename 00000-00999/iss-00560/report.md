# Result Summary

詳細: [Report Guide](../../../docs/authoring/report.md)

## Outcome

構造の図（入れ子）の配置を、依存の矢印でつながったものが同じ行に左から右へ並び、つながっていないまとまりは画面の見える幅で折り返す形に変えた（epic-00427 plan.cue の slice `iss-00560`、Epic R-15 の #560 の一文、統括が利用者に確かめた案B）。提供側の `views/graph/layout.js`、`views/graph.js` とテストだけを変えた。配布資産の文書、`static-inventory.json`（dashboard の資産は載っていない）、版の番号、`migration.md` は変えていない。

1. **兄弟どうしの依存と段（R-01、F-02）**：同じ親の、図に出ている子について、配下を含めた依存から兄弟どうしの辺を作る（モデルの `child_stages` と同じ数え方。終わった子を出さない枠では開いたものだけ）。輪は、強い順（兄弟そのものどうし → 開いたものどうしの依存の数 → 依存の数 → 元の番号 → 先の番号）に辺を残し、輪を閉じる辺を外す。段は残した辺の最長の道で数える（輪がなければモデルの段と同じ）。
   - 実データの原因：init-00423 の epic-00427 と epic-00547 が、配下の終わった Issue どうしの依存（iss-00549 → iss-00552、iss-00534 → iss-00554）で輪になり、モデルの `stage.all` が 427・547 で空になっていた。そのため 425・427・471 が同じ段に縦に積まれていた。今は 427 → 547 を残し、547 → 427 を外す（どちらの線も今までどおり描く）。
2. **まとまりの中の行（R-01）**：段の列ごとに、前のものの行の平均（.5 は上）に置き、同じ望みなら後に長く続くものが行を受け継ぐ。最初の段を活動順にした案と、後に続くものの行の順に並べ直した案を比べ、交差、上下の行き来の少ないほうを選ぶ。
3. **格子と詰めた横（R-01）**：行の高さはその行の最も高いもの。各箱は、同じ行の左の箱と依存の元の右に 44px 空けて詰める（別の行の幅の広い枠のために、つながりに空きを作らない）。経路の広げのキーは行 `rr<まとまり>`、列の後 `cc<まとまり>`。
4. **棚と折り返し（R-02、F-01）**：まとまりを活動順に左から置き、使える幅（見える幅 W − 48、枠の中はさらに枠の左右の余白を引く）を超えるところで、まとまりの境目で折り返す。棚の割り当ては経路の広げのない配置で決め、広げの繰り返しの間は変えない。W が渡されないときは 1240。最上位も同じ配置になった（最上位の枠と親のない箱を分ける扱いはやめた）。
5. **幅で並べ直す（R-03）**：`graph.js` は `clientWidth − 16` を `width` として渡し、並べ直しの合図に含める。`resize` では幅が変わったときだけ描き直し、倍率と位置は保つ。
6. 木の表し方は変えていない。

### 判断

- 案B（つながっていないまとまりは活動順に左から並べ、使える幅でまとまりの境目で折り返す）は、統括が利用者に確かめた（2026-11-04）。
- 入れ子の左右の段は、モデルの段ではなく配置の中で数える（上の輪の原因のため）。箱の「何段目」の印は今までどおりモデルの `stage.open` で、開いた子孫を持つ終わった子の配下を待つ兄弟などでは、印と左右の位置がずれうる（仕様のレビュー round 2 の P3。情報）。

### 統括への依頼（Epic の文書。この Issue では変えていない）

- Epic R-15 の text の「依存が長く続いても、枠や箱が多くても、行を折り返さずに右へ広げ、画面を横に動かして見る」と、acceptance の「長い依存の折り返し」は、#560 の一文（つながっていないまとまりは画面の幅で Epic の単位で折り返す。つながりの途中では折り返さない）と食い違う。直しをお願いしたい。

### 0.6.0 の後の移行の注記の材料（契約の変更）

- 構造の図（入れ子）は、依存の矢印でつながったものを同じ行にそろえて左から右へ並べ、つながっていないまとまりを、画面の見える幅（倍率100%）で、まとまりの境目で折り返して下へ積む（#556 の「折り返さず右へ広げる」を改める）。ウィンドウの幅が変わると並べ直す（拡大・縮小では並べ直さない）。
- 兄弟どうしの依存が輪になるときは、1本を外して左右の順を決める（線は今までどおり描く）。
- 構造の API と保存した見せ方は変わらない。
