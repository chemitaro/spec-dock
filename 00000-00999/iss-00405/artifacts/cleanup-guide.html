1. 背景

SpecDockの更新方式は、個別ファイルを賢くmergeする方式ではなく、ツール領域を6ディレクトリ単位で削除・コピーする方式へ簡素化されました。しかしruntimeとtestsの一部には、以前のprovider世代を認証するshared lease、generation witness、full-tree capability gateが残っています。文書にも旧descriptor/source-resume保証が残り、現在の実装責務と一致していません。

重要な区別: provider世代認証を削除することと、worktree targetや利用者dataを守る安全検査を削除することは同じではありません。本Issueは前者だけを撤退し、後者を明示的に保持します。

2. 用語

source commit binding

Git操作が読む内容をfull commit object IDで固定することです。repository directoryのshared lockではありません。

target binding

worktree directoryをno-followでopenし、device/inodeとEX lockで同じ対象へ固定することです。

consumer hook bound cwd

作成済みworktreeの同じinodeをcwdとしてmake initへ渡す境界です。

非transactional update

6ディレクトリを順次交換し、途中失敗時は混在を許容して外部installerを再実行する方式です。

4. 新しい実行方式

      
Issue checkout

      
    
        
  1. 対象nodeとbranch名を解決します。
    2. 
        
  2. working treeがcleanか確認します。
    3. 
        
  3. existing branchはbranch ref、新規branchは現在HEADをfull commit IDへ固定します。
    4. 
        
  4. Gitのnative switch/createを実行します。
    5. 
        
  5. branchとHEADが期待値と一致するか確認します。
    6. 
        
  6. active stateを書き、post-syncします。
    7. 
      

      
executable hook、fsmonitor、custom attribute、sparse checkoutは、存在するだけではSpecDock独自の拒否理由になりません。Git自身が失敗した場合は、その失敗を返します。


      
Worktree

      
sourceはcommit IDで固定し、source directory FDはsame-filesystemのprobeだけに使います。targetはno-follow + EX lock + device/inodeで固定します。git read-treeだけは、target FDをcwdへ変換する限定helperを使用します。provider shared leaseは持ちません。
