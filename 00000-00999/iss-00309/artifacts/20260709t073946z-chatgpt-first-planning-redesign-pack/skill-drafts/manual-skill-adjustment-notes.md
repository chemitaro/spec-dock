# Manual skill adjustment notes

## Purpose

Manual planning skills preserve the previous local/Codex-first planning workflow as an emergency fallback.

## Policy

Manual skills must not be the normal planning route. They exist because ChatGPT browser automation can be unavailable, but they require explicit human approval.

## Required Adjustments

1. Move manual workflow language out of the primary planning spine.
2. Mark manual planning as human-approved emergency fallback.
3. Prohibit automatic fallback on timeout, tab saturation, transient browser failure, or validation rejection.
4. Preserve the same final artifact quality expectations as ChatGPT-first planning.
5. Remove separate workflow-mode language from Issue Planning. If older manual wording needs variants, describe them as input context differences.
6. Keep token-saving grade concepts as manual-route implementation concerns, not ChatGPT-first core concepts.
7. Route final artifacts through the same adoption/reviewer gate expectations.

## Completion Conditions

- Manual skill names are clearly suffixed with `-manual`.
- Primary skills remain ChatGPT-first.
- Manual skills say they require explicit human approval.
- Manual skills do not claim execution readiness without reviewer gates.
