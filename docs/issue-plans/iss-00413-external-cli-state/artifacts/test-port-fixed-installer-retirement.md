# 旧fixed-source installer・journal・復旧executorの退役

## 対象と方針

採用済み[旧source置換表](../design.md#d-11)と[D-12移行契約](../design.md#d-12)に従う。読取基準は `fa6ed98c981602855489c940031515aff429aba0`。旧installer五source filesの1750行・58 top-level symbolsと、二integration／一unit test filesの1378行・56 test関数を全文確認した。候補外source/test importはpackage／絶対／相対／TYPE_CHECKING／from-import子moduleを含め0。

旧処理は固定GitHub sourceのtag/commitを解決し、archiveを取得・展開し、engine candidateと資産を照合した。Git共通領域のgroup/child UUID journal、ignored recovery areaのstage/backup/displaced/ignore marker、全managed rootの交換、maintenanceとresume/rollbackを前提にしていた。

現行は通常外部packageのversion/static manifest/実資産を使い、一つの明示WTだけを扱う。既知byte/hashだけを外部へ実体保全し、別scratchへの復元も照合してから個別fileを公開・退役する。今回のsnapshot後の変更とunsafe file/parentは停止する。旧engine取得・新journal・全WT更新・自動rollback・互換aliasを残さない。未知file/consumer仕様/選択/ignore/旧Git情報は保全する。

旧backup子inodeによるrollback所有認証と現行のbackup root identity/bytes/digest検査は同じ保証ではない。旧archive downloader/parserを温存しているとも主張しない。採用仕様で廃止した実行入口と、現在必要なsafetyの試験を分けて対応づけた。

同じrowのsymbolsには同じ判断を適用する。

| 旧module | symbols | 後継／退役理由 |
|---|---|---|
| installation/__init__ | （docstringだけ） | 旧planning/recovery packageのdocstring入口も削除。空packageや互換aliasを残さない |
| installation/group_journal | InstallationTarget、InstallationGroupRecord、child_operation_id、_directory、_validate、read_group_record、write_group_record | 全WT target/child UUID/epoch/engine/phaseのGit内group正本・更新を廃止。旧資料はreadonly診断だけ |
